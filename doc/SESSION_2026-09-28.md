# September 28 bench summary

Today's code is on **`fix/actuator-stability`**, based on teammate commit
`147896c`. It retains the integrated Part 3/4 implementation and current-sensor
backend; it is not a rollback to the September 26 firmware. `main` has not been
updated with this branch.

## Changes

- Moved Pi and Windows diagnostic writes to bounded background queues so slow
  logging cannot block the command path. Configured the Windows wheel timers
  for 20 ms and added command-gap diagnostics.
- Added MCU timeout/input/overflow counters and servo-output diagnostics, plus
  quiet/no-ADC profiles to help separate software and hardware causes.
- Enabled the third ACS712-05B sensor: right motor on A1/PA1. Firmware defaults
  to all three channels and the Windows display shows left motor, right motor
  and servo. Retained a two-sensor profile for comparison.
- Updated the Windows build helper and regression tests. Motor gains, speed
  policy, watchdogs, steering calibration and read-only current policy remain
  unchanged. No automatic current-based cutoff was added.

## Verification

- Built with Zephyr 4.3.0 / SDK 0.17.4 and flashed the three-sensor image from
  functional commit `73cc32f`. Generated pin/timer/ADC configuration checks passed.
- Latest Python discovery: 70 passed, 4 host-GCC-dependent skips. Separate
  protocol suite: 10 passed. Earlier QEMU integration: 46 passed, including
  current-channel masks 0, 5 and 7.
- User reported a steady hands-off check, steering holds and three motor runs.
  Later recordings still contain transient command timeouts; the intermittent
  movement investigation is **not closed**.
- Recorded intentional bad-range rejection and recovery. The MCU reported
  `ERROR_BAD_INPUT`; this is separate from current-sensor testing and does not
  establish physical braking latency.
- All 4650 complete USB diagnostic groups in the three-sensor recording showed
  valid mask 7 and ADC error 0. The last right-wheel obstruction attempt showed
  about 4 RPM on the right while the left kept spinning, with a captured right
  reading of -1.166 A and no new timeout during that attempt.

## Still needed

Current readings use nominal calibration: motor-rest readings around +0.7 A
must not be treated as calibrated currents. Measure zero offsets/reference and
check polarity; complete separately identified rest/running/brief-stall records
for each sensor. Also investigate the remaining link timeouts and measure the
required physical response times before claiming full checkoff completion.

Detailed evidence: [actuator stability](ACTUATOR_STABILITY.md) and
[current-sensor bench record](CURRENT_SENSOR_HANDOFF.md#remaining-part-35-bench-record).
Personal operating instructions, raw captures and host-specific analysis files
remain local. Deploy the updated Pi dependencies and Windows wrapper as well as
firmware when reproducing this branch; the firmware alone does not include the
host-side logging changes.
